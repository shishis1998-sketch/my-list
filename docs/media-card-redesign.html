MY-LIST · 媒体页改版提案 · 2026-08

封面卡片 + 详情页

把现在的十列表格拆成两层：列表只留封面、书名、作者、结束时间，点进去才展开评分、状态、时间跨度、标签和备注全文。 下面是列表 4 版、详情 3 版，都用 index.html 里现成的 token 画的，颜色字号即所见。

现状 10 列表格 数据字段 13 个 列表版本 A–D 详情版本 1–3 cover 字段已存在，只是没显示
前提

字段怎么分两层

卡片＝认出它；详情＝回忆它

卡片上每多一个字段，认书的速度就慢一点。判断标准很简单：翻列表时会用到的留在卡片上，翻完之后才想看的进详情页。

字段卡片详情理由
cover 封面●●认书最快的一眼，数据里一直有，只是列表没画
name 书名●●—
creator 作者●●同名书、同作者串读都靠它
watchDate 结束时间●●你的清单本质是「读完记录」，这是排序主键
status 状态◐ 一个色点●只填了开始时间的「进行中」得能一眼分出来，但不必写字
score 评分○●星星占一整行宽度，收益不抵成本（D 版例外）
type 分类○●顶部已经按分类筛过了，卡片再标一遍是重复
year 作品年份○●和结束时间两个年份并排，容易读错
startDate 开始时间○●详情页里和结束时间合成「读了多少天」
tags 标签○●数量不定，最毁版式的字段
note 备注○● 全文详情页有整屏，从此不用再折叠/展开
首次添加○●由 id 反解，放详情页页脚

结论

建议怎么配

主推：版本 B（横向卡片）＋ 详情 1（整页推入）

B 对封面缺失最宽容——你库里不是每条都有 cover，而 A 和 D 一旦缺图就是成片灰块。等封面补齐了，把网格布局作为「视图切换」加在排序条旁边，A 随时能接上，卡片数据完全一样。

详情选 1 而不是 2，是因为备注是这个 App 里最长的字段，半屏抽屉迟早要在里面再滚一层；而且详情 1 落地后，列表里那套折叠／展开胶囊可以整块删掉。

落地顺序动到哪里说明
1render() 的 tbody.innerHTML整块换成卡片列表；表格 colgroup／thead 一起删，td:nth-child 那批样式跟着清
2新增 openDetail(id)参照 calRoot 做成和 .content 平级的同级视图，不做浮层
3封面兜底无 cover 时画分类 emoji 占位，和日历行的 .cal-row-cover 同一套
4删除折叠逻辑toggleCnoteCard、.cnote-toggle、note-expanded 全部退休
5左滑手势enhanceMediaSwipe 从 tr 改绑到卡片元素
