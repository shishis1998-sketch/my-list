去掉封面之后

方向已定：横向卡片列表 ＋ 整页详情。这一版回答「封面拿掉长什么样」——没有封面，卡片就少了左边那块视觉锚点，行会矮下去、也会平下去。

下面先并排看去掉前后的差别，再给三种补锚点的排法：N1 纯文字、N2 日期当锚、N3 首字方块。详情页也一并改成无封面版。

卡片高 86px → 58px 一屏 5 本 → 7–8 本 卡片字段 书名 · 作者 · 结束时间 cover 字段 保留在数据里，不显示
对照

去掉前 / 去掉后

同一批书，同样的屏幕高度

排法 N1

纯文字

书名 / 作者 左对齐 · 日期右对齐 最干净

什么都不补，一整块白底列表，行与行之间只有一条发丝线。日期靠右成一列，年份省掉只留「月.日」——同一年的记录本来就不用重复写年份，跨年时那一行补成「2025.12.30」。

好处

  • 最省，改动也最小：一个 div 就够
  • 书名有整行宽度，长副标题不挤

  • 状态只能靠「在读」两个字，弱
排法 N2

日期当左锚

把结束时间搬到封面的位置 推荐

封面腾出来的那 44px，交给最该被看见的字段：结束时间。日号 17px 粗体、月份 10px 灰字压在下面，靠左成一条数字轴。左边缘重新有了节奏，而且这次是有信息的节奏——不像封面只是好看。

排法 N2+

再加月份分组

月份提到标题行，左列只留日号 最像阅读记录

结论

建议选 N2

N2 日期当左锚 ＋ 按结束时间排序时自动分月

去掉封面之后唯一真正的损失是「左边缘没有落点了」。N3 用首字方块补，补的是装饰；N2 用日期补，补的是这个 App 里最该被看见的字段——你的清单本来就是一份读完记录，日号成列之后，翻列表就是在翻流水账。

N1 也留着：它其实就是 N2 关掉左列的样子。按书名或评分排序时日期轴失去意义，自动退回 N1，同一套 DOM，去掉一个 div 而已。

顺序动到哪里说明
1render() 的 tbody.innerHTML整块换成 .list-n 行式；table / colgroup / thead 一并删，样式表里成片的 td:nth-child(n) 跟着清
2日期左列watchDate 拆成日号 + 月份两行；只有 startDate 的记录画蓝色「起」
3分月分组仅在「按结束时间」排序时生效，其余排序退回 N1
4新增 openDetail(id)参照 calRoot，做成与 .content 平级的同级视图，用 --nav-* 转场
5删除折叠逻辑备注全文进详情页，toggleCnoteCard / .cnote-toggle / note-expanded 一起退休
6左滑手势enhanceMediaSwipe 从 tr 改绑到 .n-row
7封面字段编辑弹窗里的「封面链接」输入框收起来；item.cover 保留在数据里不动，日历页仍在用
