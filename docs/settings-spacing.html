改之前先知道这几条

WIDTH

设置页的卡片宽 364，媒体列表的卡片宽 365。差的这 1px 是侧栏的右边框：手机版式里写了 border-right:none（index.html:728），但后面报纸风那段又整体重写了一次 .sidebar{…border-right:var(--bd) solid var(--ink)}（index.html:2104），同特异性、位置更靠后，于是赢了。可用内容宽因此是 392 而不是 393。

EDGE

卡内的起排线现在只有一条：30 = 页边距 14 + 卡片描边 1 + padding 15。原先行是 14、经期参数与色块是 10、分组标题是 8，四处各排各的；现在统一写成 15，把描边那 1px 也补进去。15 不在 --sp-* 那把尺上——尺是 …12 / 14 / 16…，没有能补掉 1px 描边的档，所以这里是个写死的数，改页边距或描边宽度时得跟着算。

TEXT

起排线统一了，文字左沿仍是三档：30（无图标行）、46（分类行，圆点 8 + gap 8）、51（图标行，图标 13 + gap 8）。图形本身都从 30 起，是它们的宽度把文字顶开的。想让文字也齐平，只能给行首图形一个定宽槽（比如都占 13），或者干脆不要图形——那是另一个决定，这版没做。

TITLE

分组标题（数据 / 同步 / 外观 / 分类管理 / 经期）在手机端整屏设置页已整体隐藏（.sidebar .nlbl{display:none}，index.html:776）。五张卡靠 24 的间距分组，页面因此矮了 224（1399 → 1175）。桌面端侧栏没动——那边的标题是主导航的一部分。

FONT

经期卡里所有本该是小字的地方写的都是 var(--fs-micro)，而这个变量只在 #calViewPeriod 的作用域里定义（index.html:2338）。设置页取不到值，整条 font-size 声明作废，字号回落到继承来的 15——所以那几行看着和主行一样大。

TAP

行高 48 来自 min-height，不是内容撑的：12 + 17 + 12 = 41，剩下的 7 是为触控留的。带控件的行会超过 48（主题 57、字号 58、排卵 49），高度由控件定，padding 不变。色块从 32 缩到 26 后触控节距变成 34，是这一页里最小的点击目标。

ORDER

分组次序是 order 排的：数据 −4 → 同步 −3 → 外观 −2 → 分类管理 0 → 经期 0（index.html:741）。DOM 顺序仍是桌面端侧栏那一套，换序只动手机端。要在中间插一组就整体重编号，别指望在相邻两个负数之间塞。

SCROLL

整页高 1175，视口 852——设置页要滚 1.4 屏。页头 sticky 钉顶，底部 76 是给常驻底栏让的位，末组的 24 不会被它吃掉，两份是叠加的。
