改之前先知道这几条

WIDTH

设置页的卡片宽 364，媒体列表的卡片宽 365。差的这 1px 是侧栏的右边框：手机版式里写了 border-right:none（index.html:728），但后面报纸风那段又整体重写了一次 .sidebar{…border-right:var(--bd) solid var(--ink)}（index.html:2104），同特异性、位置更靠后，于是赢了。可用内容宽因此是 392 而不是 393。

EDGE

同一页里文字的左沿有 五个：22（分组标题）、25（经期参数 / 色块）、29（无图标行）、45（分类行）、50（图标行）。前四个是各自 padding 的差，最后两个是前置图形宽度的差（图标 13 vs 圆点 8）。要对齐，改的是前置图形的容器宽度，不是文字的 margin。

FONT

经期卡里所有本该是小字的地方写的都是 var(--fs-micro)，而这个变量只在 #calViewPeriod 的作用域里定义（index.html:2338）。设置页取不到值，整条 font-size 声明作废，字号回落到继承来的 15——所以那几行看着和主行一样大。

TAP

行高 48 来自 min-height，不是内容撑的：12 + 17 + 12 = 41，剩下的 7 是为触控留的。带控件的行会超过 48（主题 57、字号 58、排卵 49），高度由控件定，padding 不变。

ORDER

分组次序是 order 排的：数据 −4 → 同步 −3 → 外观 −2 → 分类管理 0 → 经期 0（index.html:741）。DOM 顺序仍是桌面端侧栏那一套，换序只动手机端。要在中间插一组就整体重编号，别指望在相邻两个负数之间塞。

SCROLL

整页高 1399，视口 852——设置页天生要滚 1.6 屏。页头 sticky 钉顶，底部 76 是给常驻底栏让的位，末组的 24 不会被它吃掉，两份是叠加的。
