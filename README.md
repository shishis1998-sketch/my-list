## 🗂️ 这个 App 是怎么搭起来的

```
┌─────────────────────────────────────────────────┐
│  手机/电脑浏览器                                  │
│  ┌──────────────────────────────────────────┐  │
│  │  打开网址 → 加载 index.html                │  │
│  │  网页运行 → 数据存浏览器 localStorage      │  │
│  │  改动后 → 1.5 秒自动推送到 GitHub Gist     │  │
│  └──────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
              ↓                    ↑
         (访问)                  (云同步)
              ↓                    ↑
┌──────────────────────┐  ┌──────────────────────┐
│  GitHub Pages        │  │  私密 GitHub Gist    │
│  托管 index.html     │  │  存数据 JSON 文件    │
│  永久免费、无广告    │  │  永久免费、私密      │
└──────────────────────┘  └──────────────────────┘
```

**三件东西彼此独立：**

| 类别 | 存哪 | 备份方式 |
|---|---|---|
| **代码** index.html | GitHub 仓库 | GitHub 自动有版本历史 |
| **数据** JSON | 私密 Gist | 手动「导出 JSON」+ 本地存档 |
| **配置** Token + Gist ID + 主密码 | 浏览器 localStorage | 重新输入即可（主密码要记牢！）|

任何一个出问题，**另外两个不受影响**。

> ⚠️ **代码里不放任何数据。** index.html 是公开的（仓库和 GitHub Pages 都必须 Public），
> 所以媒体、笔记、经期记录一律不写进这个文件——它们只活在本机 localStorage 和私密 Gist 里。
>
> **新设备刚打开时一片空白是正常的**，填完 Token + Gist ID 才会有数据。
> 以后改代码也请守住这条：**别把任何真实记录当「种子数据」写进 index.html**，
> 那等于公开发布，而且会覆盖掉每台新设备的本机数据。

## ☁️ 云同步设置步骤

云同步需要填**三样东西**，都在「云同步」设置弹窗里：

| 填什么 | 作用 | 哪里来 |
|---|---|---|
| **Token** | 让网页有权限读写你的 Gist | GitHub 生成（见下方步骤 1）|
| **Gist ID** | 指明数据存在哪个 Gist | 首次留空、确认后创建（见下）|
| **主密码** | **加密整份云端数据** | 自己想一个，**要记牢** |

### 入口在哪

- **电脑**：左侧边栏最底部 →「同步」→「云同步」
- **手机**：右下角「设置」（或左上角菜单）打开侧边栏 → 滚到最底部 →「云同步」

### 第一台设备（首次设置）

1. **生成 Token**：登录 GitHub → 头像 → **Settings** → 左侧最底 **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**
   - Note 随便填（如 `media-tracker`）
   - Expiration 选 **No expiration**
   - 权限**只勾 `gist`**
   - 生成后**立刻复制**（页面关掉就再也看不到了）
2. 打开网站 → 云同步设置 → 粘贴 Token
3. **Gist ID 留空** → 保存时会弹一个确认框问你「确实是第一次启用吗」，确认后才创建私密 Gist
   （这道确认是防呆用的：以后如果你已经有云端了却把 Gist ID 填漏，点「取消」就不会凭空多出第二份云端）
4. 填一个**主密码**（加密整份云端数据，见下方说明）——**强烈建议填**，不填则 Gist 里全是明文
5. 点「保存并同步」→ 右下角提示「已创建云端备份」即成功
6. 回到设置弹窗，**把自动生成的 Gist ID 抄下来**（换设备要用）

### 换设备 / 新设备

1. 新设备打开 https://shishis1998-sketch.github.io/my-list/
   → **页面是空的（媒体 0 条、经期页也空），这是正常的**，数据还没拉下来
2. 打开云同步设置，填**同一个 Token + 同一个 Gist ID + 同一个主密码**
3. 点「保存并同步」→ 数据自动从云端拉回，备忘自动解密

> ⚠️ **Gist ID 一定要填。** 只填 Token 不填 Gist ID，这台设备既不会上传、也拉不到东西
> （同步徽章会显示「缺少 Gist ID，已跳过上传」）。这是刻意的：宁可什么都不做，
> 也不能猜成「第一次启用」而新建一份只含这台设备数据的云端。

### 副机 / 借来的设备（只想看，不想改）

**顺序很重要：先开只读，再填 Token。** 反过来会留一个窗口——填完保存的那一刻同步就开始跑，如果这台设备手上是旧数据，可能把云端顶掉。

1. 云同步设置 → **先勾「👀 只读模式」**（立刻生效，不用点保存）
2. 再填 Token / Gist ID / 主密码 → 点「保存并同步」
3. 看完 → 点 **「🧹 用完了，清除这台设备的本机数据」**

只读模式下这台设备**照常拉取、永远不上传**，同步徽章显示「只读」。开关每台设备各自存本机，主力机不受影响。

> 第 1 步保证它不会污染云端，第 3 步保证它不留明文。第三台设备、借别人手机看一眼，都照这个来。

### 主密码是干什么的

**填了主密码，整份云端数据就是加密的。** Gist 里只剩一团密文——媒体记录、笔记、日记、经期数据、备忘，全部盖住。就算 Gist 链接泄漏，别人打开也是乱码。

- 主密码**只存在你自己的设备上，永远不会上传**，所以每台设备都要填一次同样的
- **不填主密码 = 云端全明文**（老行为，仍然能用，但不推荐）
- 加密是自动的，不用逐条操作。备忘还额外加一层，某条想严格只留本机就点卡片上的锁图标
- 新设备填错密码不会坏事：页面显示空白 + 红色提示「主密码不对」，改对了立刻恢复
- 🛡️ **填错密码的设备不会破坏云端**：解不开就自动停止上传，不会拿空数据覆盖真数据
- ⚠️ **本机始终是明文**：加密只保护云端。数据解开后就写进了这台设备的 localStorage，**光清主密码不会清掉明文**。要真正擦干净，用「🧹 用完了，清除这台设备的本机数据」

> ⚠️ ⚠️ **主密码没有找回功能，而且现在它锁的是全部数据。**
> 它不在云端任何地方。**所有设备都忘了 = 云端数据永远打不开**（各设备本机那份还在，
> 赶紧「导出 JSON」抢救）。挑一个记得住的，并且**存进密码管理器**。
> 每月导出一次 JSON 的习惯，从「建议」升级成「必须」。

### 备忘的三种状态

点备忘卡片右上角的徽章可以切换：

| 徽章 | 含义 | 风险 |
|---|---|---|
| 🛡️ **已加密** | 加密后同步到云端，Gist 里只有密文 | 推荐。忘了主密码就解不开 |
| 🔒 **仅本机** | 只存这个浏览器，**从不上传** | 清掉浏览器数据就永久没了，得自己导出 JSON |
| 🔓 **明文上云** | 没设主密码时的状态，账号密码明文进 Gist | 不推荐，赶紧设主密码 |

> 有一批「仅本机」的备忘想一起上云？去云同步设置点 **「🔓 把 N 条「仅本机」备忘加密上云」** 一次性传上去，别一条条点。

## 📅 把 Google 日历导入「日历看板」

日历看板是**回顾型**的（「往年今日 / 当天记录」），不是排未来日程的。如果想把 Google 日历里的事件搬进来当记录看，用 `.ics` 导入即可——不需要登录、不接第三方 API，数据仍只在你自己手里。

**怎么做：**

1. 电脑上打开 **Google 日历 → 设置 → 导入与导出 → 导出** → 下载一个 `.zip`，解压得到 `.ics` 文件
2. 打开本 App → 右上角设置 → 「数据」区 → 点 **「导入日历 (.ics)」** → 选那个 `.ics`
3. 提示「日历导入完成：+N 条」即成功。每个事件会变成一条**日历笔记**，落到它自己那天

**导入后的样子：**

- 事件按日期落到日历，点那天就能看到，事件标题加粗，下面带时间 / 地点 / 描述
- 统一归到「**日历**」子分类、打「**日历导入**」标签，方便在笔记页筛选或批量管理
- 按事件 UID **去重**：同一个 `.ics` 重复导入不会产生重复条目

**注意边界：**

- **单向、非实时**：Google → App。之后改了 Google 日历不会自动同步，需要重新导出再导入
- **每周例会那种重复日程（RRULE）只导入第一次那天**，不会展开成一长串
- 建议先拿一小段 `.ics` 试导，确认满意再导全部；导入也算数据改动，会照常同步上云

## 🆘 出问题怎么查

### 问题 1：「打开网址，页面空白 / 报错」

依次尝试：
1. 等 1-2 分钟再试（GitHub 偶尔抽风）
2. 手机长按刷新按钮 → 强制刷新
3. 试试用电脑能不能打开
4. 还不行 → 访问 https://www.githubstatus.com 看服务状态

### 问题 2：「页面打开了，但数据没了」

> ⚠️ **别慌，数据没真的丢。**

排查顺序：
1. **先检查配置**：进设置（左侧菜单），看 Token 和 Gist ID 是否还在
2. **如果 Token 在但数据不显示**：可能是 Gist ID 错了。去 https://gist.github.com 找到 `media-tracker-data.json` Gist，从 URL 复制 ID 重填
3. **如果 Token 不在**：浏览器缓存被清了。重新填 Token 和 Gist ID，数据自动从云端拉回
4. **如果还是没数据**：用最近 JSON 备份恢复（导入 JSON 功能）

> 只有**备忘**少了？那是另一回事，看「问题 5.7」。

### 问题 3：「同步状态显示红色 / 错误」

最常见原因：**Token 失效**（见下方）。

其他可能：
- 网络问题 → 换 WiFi
- GitHub 服务异常 → 等等
- 仓库变私密 → 检查 https://github.com/shishis1998-sketch/my-list 是否还是 Public
- 提示「**缺少 Gist ID，已跳过上传**」→ 这台设备只填了 Token。把 Gist ID 补上即可，
  不是故障（是刻意不让它自动新建第二份云端）
- 提示「**尚未与云端对齐，已暂停上传**」→ 拉取没成功过，先修网络 / Token，
  别急着改数据（这道闸门是在保护云端不被旧数据顶掉）

### 问题 4：「Token 失效怎么办」

虽然选了「永不过期」，但以下情况 Token 会失效：
- GitHub 检测到 Token 被泄漏
- 你主动撤销了
- 账号安全策略变化（罕见）

**重新生成步骤：**

1. 登录 GitHub → 右上角头像 → **Settings**
2. 左侧最底 → **Developer settings**
3. **Personal access tokens** → **Tokens (classic)**
4. **Generate new token (classic)**
5. 设置：
   - Note：随便填，比如 `media-tracker`
   - Expiration：**No expiration**
   - 勾选权限：**只勾 `gist`**（别多勾！）
6. 生成后 **立刻复制**（关掉就再也看不到了）
7. 打开网站 → 设置 → 粘贴新 Token → 保存

### 问题 5：「想在新设备上用」

换手机或电脑：
1. 新设备打开 https://shishis1998-sketch.github.io/my-list/
2. 进入云同步设置
3. 填入**相同的 Token、Gist ID 和主密码**
4. 数据自动从云端拉取，备忘自动解密

> ✅ 不需要重新搞 Token。同一个 Token 多设备共用。
>
> ✅ 刚打开时页面空白（0 条记录、经期页也空）是正常的，不是数据丢了——填完配置就回来了。
> Gist ID 别漏填，漏了这台设备就是个空壳，什么也不会发生。

### 问题 5.5：「页面空白，提示需要主密码 / 主密码不对」

云端整份是加密的，这台设备解不开：

1. 打开云同步设置，填**正确的主密码**
2. 点「保存并同步」→ 数据立刻回来，不用重开页面
3. 数据不会丢——密文一直在云端，填对就能解开

> 🛡️ 这种状态下这台设备**自动停止上传**，不会把空白覆盖到云端。放心慢慢试密码。

### 问题 5.6：「备忘显示 🔒 已加密，看不到内容」

同上，填对主密码即可。备忘在整份加密之外还单独加了一层，所以偶尔会出现
「其它数据都正常、只有备忘显示 🔒」——补上主密码就解开了。

### 问题 5.7：「备忘少了一大批 / 只剩几条」

> ⚠️ **别急着到处点，尤其别反复刷新页面。**

**两条补救路径，按顺序试：**

1. **「↩ 还原到覆盖前的备份」**（云同步设置里）——本机快照，覆盖发生前自动存的，最省事
2. **「导入 JSON」** ——用你自己导出的备份恢复

> ℹ️ 以前还有个「从云端历史版本找回」的功能，翻 Gist 的历史版本捞回被删的笔记，
> 已经移除。所以**你自己导出的 JSON 备份变成了最后一道防线**——每月导一次，别偷懒。

**为什么会发生**（2026-07 修复前的老问题，了解即可）：

同步的规则是「云端覆盖本地」——每次打开 App，云端没有的，本机一律删掉。而上传是**整份覆盖**：把本机当前内容打包，整个盖掉云端。所以只要有**一台设备手上是旧数据**，它随手改条笔记触发推送，就会把云端顶掉；接着每台设备一开机，都照着这份缺失把本机备忘删干净。两步之间可能隔几小时，完全看不出因果。

**现在的防护**（都已上线）：

- 没跟云端对齐过（本会话没成功拉取过）的设备，**不准覆盖云端**
- 云端没有、本机有的备忘，**不再删除**，改为标回「仅本机」并提示
- 上云失败会自动退回「仅本机」，不留「以为传上去了」的假状态
- 会清空云端备忘的操作（清主密码、断开同步）现在都要确认，写明后果
- 云端条数比本机少时当场告警，并自动存一份还原点

### 问题 6：「网页突然变丑 / 某些功能不工作」

很可能是浏览器和 CSS 兼容问题：
1. **强制刷新**（iPhone 长按刷新按钮 / 电脑 Ctrl+Shift+R / Mac Cmd+Shift+R）
2. 试试**电脑或别人手机**打开，看是不是只在你设备上有问题
3. 截图描述问题，找 AI 助手帮改 CSS

## 🔐 安全注意事项

### Token 不能泄漏

Token = 密码。拿到 Token 的人可以：
- 看你**所有**私密 Gist
- 修改 / 删除 Gist

**预防：**
- ❌ 不在公共电脑登录
- ❌ 不发给陌生人
- ❌ 不贴朋友圈/微博等公开地方
- ✅ 万一泄漏 → 立刻去 GitHub 撤销旧 Token + 生成新的

### 私密 Gist 有多私密？

私密 Gist **不会被搜索和公开列出**，但**拿到链接的人不用登录也能看**——
「私密」的意思是「不公开列出」，不是「需要授权」。

所以别只靠它：**填了主密码后，整份数据在上云前就已经加密**，
Gist 里只有一团密文。链接泄漏也读不出任何内容。

没填主密码的话，Gist 里是明文的——媒体、笔记、日记、经期数据全部可读。
拿到链接就等于拿到全部数据。**建议填主密码。**

### 主密码不能忘

主密码只存在你自己的设备上，**云端没有、无法找回**。
忘了 = 云端的备忘密文永远解不开（各设备本机已解密的副本还在）。

### 别把明文留在别人的设备上

备忘解密后，明文就存在那台设备的浏览器里了。副机、借来的手机看完，
用「🧹 用完了，清除这台设备的本机数据」擦干净——它会连同已解密的明文、
主密码、Token 一起清掉，**云端 Gist 不受影响**，重新填 Token 就能再拉下来。

如果那台设备上还有「仅本机」的备忘（云端没副本），按钮会拦一道让你先上云或导出 JSON。

### 仓库为什么要 Public？

GitHub Pages 免费版**只支持公开仓库**。公开的是代码（index.html），数据在私密 Gist 里。

⚠️ **但这条只在「代码里确实没有数据」时才成立。** 早期版本曾把经期记录当种子数据
硬编码进 index.html，那段时间它是随网页一起公开的。现在已经清掉（见「这个 App 是
怎么搭起来的」里的提醒），但**旧 commit 里仍然留着**——
https://github.com/shishis1998-sketch/my-list/commits 翻得到。

真要彻底清除，只能重写 git 历史（`git filter-repo` + 强制推送）或删库重建。
已知悉、暂不处理；记在这里是为了别忘了这回事。

## 🛠️ 想改 App 怎么办

### 小改动（CSS、文字、布局）
1. **先「导出 JSON」备份**
2. GitHub 仓库 → `index.html` → 铅笔图标 ✏️ → 直接改
3. 改完 Commit
4. 等 30 秒-2 分钟，强制刷新

### 大改动（加功能、改逻辑）
找 AI 助手（Claude / ChatGPT）：
- 告诉它想加什么功能
- 把当前 index.html 发给它
- 让它给你完整改后的新文件 + 改动清单

> 🚫 **一条硬规矩，改之前先说给 AI 听：**
> **index.html 里不许出现任何真实记录。** 不管叫「种子数据」「示例数据」还是「默认值」，
> 只要写进这个文件，就等于发布到公网（仓库和网页都是 Public），而且每台新设备一打开
> 就会被它覆盖本机数据。数据一律走 localStorage + 私密 Gist，新设备空着是对的。
>
> 收到 AI 改好的文件后，搜一下有没有你自己的记录混进去，再提交。

### 改坏了怎么办
1. GitHub 仓库 → 点 **Commits**（Code 标签页顶部）
2. 找到上一个能用的 commit
3. 点 **⋯ → Revert** → 回退
